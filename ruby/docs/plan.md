# Ruby plan

Ruby's part of the [phase 1 plan](../../docs/plan/phase-1.md): the shared slices and their acceptance criteria are
there, and its decisions in [`decisions.md`](decisions.md).

How Ruby realizes a slice, where it differs from the shared criteria.

| [S02](../../docs/plan/phase-1.md#slices) | [`ruby/docs/spikes/claude-features.md`](spikes/claude-features.md): all seven features typed in the `anthropic` gem; blocks written canonical from the gem's `to_json` and replayed byte for byte as `JSON::Fragment`s through `extra_body: {messages:}`, as typed `messages` re-encode (R9); nilable model fields read raw, as one set to `nil` through a setter raises (a streamed compaction block's `encrypted_content`) |
| [S03](../../docs/plan/phase-1.md#slices) | `Agent#run` yields events and returns the result; `Cancellation` (R10); blocks as frozen canonical strings (R9), pinned by a test that parses and writes again a conversation holding `<`, `&`, non-ASCII and `\u` escapes; the thread-leak check (R11); a block that `break`s mid-run leaves no thread; 100 concurrent runs in threads; sets the core line budget (R14). Outcome: the model contract is an RBS `_Model` whose `stream` yields deltas and usage and returns the reply; the loop and the 25-call limit run, each tool call answered with an error result until S05; the prefix fingerprint already matches `testdata/session/prefix.json`; TEST-02 across a restart resumes in a child Ruby process; budget 2,800 code lines (412 now) |
| [S04](../../docs/plan/phase-1.md#slices) | The model settings string the fingerprint uses, as .NET's and Go's; the shared golden request layouts; a reply's `tool_use` blocks never left without results; retries on recorded HTTP (`webmock`), `Retry-After` included; `examples/hello`. Outcome: `Claude::Model` streams on the beta API, stored blocks replayed as `JSON::Fragment`s through the one raw field (R9); retries on a local `TCPServer` fake API rather than `webmock` (cut connections as the client sees them, no new dependency); the core gains `Retried` and `Cancellation#on_cancel`; the run (S03) already keeps no reply whose calls go unanswered; hello cached from the second message live ($0.03) |

Outcome of B: tools from the DSL or a `Schema`, with a block handler taking the input and the run's `Cancellation`; the pipeline on its own thread hands events over a `Thread::Queue`; reads on threads, joined before a write; approvals through an `_Approver`; the audit recorder and a JSON-lines sink; redaction of every JSON form of a secret; the scripted approver and a recording sink in the test kit; the run engine split into the loop, the reply's outcome, the tool step and the host link; `ruby-mutation` gates: no survivor in changed methods on a PR, 99% on full runs (measured 99.47%) |
| [S06](../../docs/plan/phase-1.md#slices) | In two parts, so the first runs beside Ruby S05: **A**, the data layer, `apps/bookshop` on `pg` and `connection_pool` (R7), its catalogue, customers and orders over fixed SQL, a refusal raised as one error class, tested against PostgreSQL in Docker (R12); **B**, once the tool pipeline (Ruby S05 part B) exists, the nine tools on the core's tool API, the console with streaming, approvals, Ctrl+C through `trap("INT")` pushing to a queue that the console's own thread reads to cancel the reply (R10), `/help`, `/quit` and run context, with its end-to-end tests. Outcome of B: the nine tools in three modules, their names, descriptions and schemas checked against .NET's bytes, results in .NET's JSON with amounts to the penny (`Money`); `Bookshop.build` composes shop, tools, approver, agent and console, and `exe/bookshop` runs it; approvals through a queue of answers tagged with their call; each line read on the terminal's own thread, so Ctrl+C stops an approval prompt at once; connect and statement timeouts; end-to-end tests of APP-01, 02, 03 (mid-stream and at the approval prompt, with a real `SIGINT`), 05, 06, 07, 09, 13 and 18 against PostgreSQL in Docker |
| [S07](../../docs/plan/phase-1.md#slices) | In two parts: **A**, the core: the OpenTelemetry API with host-passed providers through one `Telemetry` per provider pair (R6), the metrics API's version rechecked, `_Model#info` with its price, audit entries with their trace and span, sink failures in telemetry, the SDK's in-memory exporter and reader in tests only, the names checked against .NET's and Go's sources, and the TEST-07 secrets property; **B**, the application: OTLP/HTTP to the dashboard and logs (R16), the audit table sink with trace ids, and `/audit`. Outcome of B: each reply a `reply` span over its run, with its log record through a `Logger` bridged to OpenTelemetry; the metrics and logs exporters sent uncompressed, as the dashboard rejects gzip; checked live: a reply was one trace on the dashboard (reply, run, two model calls, a tool call) and `/audit`'s link opened it |

In two parts: **A**, the core's budgets, results' usage and cost, interrupted calls and the audit entry's cost; **B**, Bookshop's sessions and budgets. Outcome of B: the sessions table as .NET and Go keep it, saved after every step with an optimistic check that never drops messages; `/new`, `/sessions` (no titles until Ruby S12), `/resume` refusing another version's session, `/cost`, the status line, and a reply's and a session's budget (`BOOKSHOP_REPLY_BUDGET`, as Go's); checked live: after quit and restart, `/resume`'s first call read 97% of its input from the cache |
| [S09](../../docs/plan/phase-1.md#slices) | Split in two to run in parallel: part A, the memory stores and path rules (`_MemoryStore`, file and in-memory stores sharing one set of tests, links refused, generated traversal paths for the scope property); part B, the memory service as Claude's memory tool through the tool pipeline, the staff member chosen at start and `/memory`, once Ruby S05 part B and the console exist |

In two parts: **A**, the core's context management, events and audit, and the Claude adapter's; **B**, Bookshop's settings (.NET's and Go's), `--demo`, and the console's lines. Outcome of B, checked live: in demo mode, nine lookups and the demo's four searches in one turn cleared 3 results and compacted 51,772 tokens into 1,520 ($0.31); the resumed session went on, reading 70% from the cache |
